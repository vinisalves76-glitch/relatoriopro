# Frontend Engineering

1. Inspect the relevant page, CSS, JS modules, event wiring and data adapter before editing.
2. Follow the existing design system and responsive patterns; do not introduce a new framework without approval.
3. Preserve existing labels, roles, permissions, navigation and operational flows.
4. Treat UI visibility as presentation only; enforce authorization on the server/database too.
5. Keep changes scoped and avoid broad refactors mixed with feature work.
6. Check loading, empty, success, error and offline states where relevant.
7. Do not claim visual or browser testing unless actually performed.
8. Update documentation only when behavior or conventions change.

Output: changed files, user-visible behavior, accessibility/responsive considerations and test evidence.
